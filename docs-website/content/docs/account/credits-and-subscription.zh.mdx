使用 CodeDAG 会消耗 CodeDAG 额度：工作流开始执行时按任务数扣除，每个任务 1 点，提交和排队都不扣。新账号注册即送 800 点，30 天内有效，不需要绑定信用卡；订阅按月付是每月 \$12，按年付是每年 \$96，都是每月 800 点。额度不够时，新的工作流无法提交，已经排队的工作流轮到执行时会停下来，等你恢复额度后再继续。怎样估算和降低一个工作流的花费，见[控制成本](/zh/docs/account/cost-control)。

## 免费额度 [#free-credits]

新账号注册即送 800 点 CodeDAG 额度，从注册那天起 30 天内有效，不需要绑定信用卡。第一次登录时 CodeDAG 会为你创建账号，额度随之到账，见[登录](/zh/docs/account/login-and-account#sign-in)。每个账号只赠送一次，30 天后没用完的部分作废。免费期间与订阅之后能用的功能完全相同，区别只在额度的来源。

免费期间可以随时订阅，不必等免费额度用完。订阅生效时，剩下的免费额度并入第一个付费周期，所以这个周期的总额度可能多于 800 点；此后账号里始终只有一份额度，按订阅周期重置。如果一直没有订阅，免费额度用完或到期之后，新的工作流无法提交，已经在排队的工作流也无法开始执行，见[额度不足或无订阅时](#insufficient-credits)。

参加过内测的账号，如果内测结束时还没有订阅，额度会统一改为 800 点，到期日为内测结束后 30 天。内测结束的具体日期以内测通知为准，转换后的到期日可以按[查看额度与用量](#check-usage)中的方式查询。

## 订阅 [#subscription]

CodeDAG 只有一个订阅方案：按月付是每月 \$12，按年付是每年 \$96，相当于每月 \$8，比月付省 33%。两种付法得到的额度完全相同，都是每月 800 点，每月重置一次，当月没用完的额度不会累计到下个月。价格也列在[定价页](/zh/pricing)上。

月付的额度随每次续费重置。年付虽然一年只付一次款，额度仍然按月发放：从订阅开始那天起，每满一个月重置一次，每次同样是 800 点。

订阅不包含第三方 AI 模型的费用：CodeDAG 调用的是你自己安装并登录的 Claude Code 或 Codex，它们的用量照常计在你自己的账号上，见[控制成本](/zh/docs/account/cost-control)。

订阅在网页控制台（[app.codedag.com](https://app.codedag.com)）的 Billing 页完成，付款由 Stripe 处理。切换付款周期、取消订阅等操作的规则见[订阅细则](#subscription-details)。

## 什么时候扣除额度 [#when-charged]

额度只在一个时刻扣除：工作流排到队首、真正开始执行之前，按工作流里的任务数一次扣清，每个任务 1 点。提交和排队都不扣，开始执行之后也不会再扣。

提交时，`cdg dag submit{:sh}` 只检查剩余额度够不够：一次提交几个工作流，就看它们的任务总数，不够时整批都不会提交。这次检查既不扣除，也不替工作流预留额度。因此，工作流在开始执行之前被取消，不会产生任何费用；但排队期间额度也可能先被别的工作流用掉，包括同一账号在其他项目或其他电脑上执行的工作流，轮到它时仍有可能不够，这时会发生什么见[额度不足或无订阅时](#insufficient-credits)。

扣多少点只看提交时工作流文件里有多少个任务，与之后实际执行了多少任务无关：中途被取消的任务，以及因为上游被取消而没有执行的下游任务，都已经计算在内。反过来，一次执行一旦开始就已经付清，之后暂停再继续、中断后恢复、审核时要求修改或推翻重做，都不会再扣；它执行期间即使额度用完或订阅到期，也不会因此停下。

同一个工作流再执行一次，就是一次新的执行，要重新计费：已经审核结束的工作流[清除审核记录后重新提交](/zh/docs/reference/cli/review#clear-and-resubmit)，开始执行时按任务数再扣一次；把没做完的任务另写成一个工作流接着跑，则按这个新工作流的任务数扣除。

<Callout type="warn">
已经扣除的额度不会自动退回。工作流开始执行之后，无论任务失败、被你取消，还是结果不理想，扣掉的额度都不退。如果是 CodeDAG 自身的问题导致工作流没能正常执行，可以按[收集信息以便求助](/zh/docs/troubleshooting/troubleshooting#get-help)中的方式联系我们。
</Callout>

## 额度不足或无订阅时 [#insufficient-credits]

额度不够时，工作流会在两个时刻被拦下：提交时直接被拒绝，不进入队列；已经在排队的，轮到它开始执行时停在 `on-hold`，不扣额度，等你恢复可用额度后再用 `cdg dag recover{:sh}` 继续。

提交被拒绝时，终端会说明原因；排队中的工作流被拦下时，`cdg dag status <名字>{:sh}` 会显示原因和处理办法。原因不同，恢复可用额度的办法也不同：

| 情况 | 怎样恢复可用额度 |
|---|---|
| 订阅在本周期的额度已用完 | 等到提示的重置时间，或者另外注册一个账号：新账号的额度和订阅单独计算，不与原账号合并。目前没有额度补充包可买，切换月付和年付也不会带来新额度。 |
| 订阅已经结束或续费扣款失败，账号没有可用的订阅 | 在 Billing 页订阅；续费扣款失败的，更新支付方式并完成付款。 |
| 免费额度已用完或已到期 | 在 Billing 页订阅，生效后即可继续提交。 |

恢复可用额度之后，排队中被拦下的工作流不会自己重新尝试，需要手动恢复它：

```bash title="Terminal"
cdg dag recover <名字>
```

它会让工作流重新尝试开始执行，这时才扣除额度；同一次执行无论恢复多少次，最多只扣一次。被拦下的工作流就停在队首，后面排队的工作流也会跟着等待，所以处理好之后要记得恢复它。

## 查看额度与用量 [#check-usage]

在命令行里用 `cdg auth status{:sh}` 查看当前账号的额度，在网页控制台（[app.codedag.com](https://app.codedag.com)）查看用量明细并管理订阅。两处显示的是同一份数据。

```bash title="Terminal"
cdg auth status
```

输出包括当前登录的账号、订阅状态、本周期已用和剩余的额度，以及本周期的起止时间；本周期的结束时间就是额度下一次重置的时间。订阅后的第一个周期包含并入的免费额度，总数可能多于 800 点。命令行和控制台的时间都按 UTC 计算。

使用免费额度期间，包括内测结束后转换的额度，`cdg auth status{:sh}` 与控制台同样会显示剩余额度和到期日。

网页控制台的 Usage 页列出本周期用量和最近 20 条扣费记录。每条记录对应一次开始执行的工作流，列出时间、任务数和扣除的额度；其中工作流一栏显示的是提交时工作流文件内容的哈希值前 12 位，而不是文件名。

## 订阅细则 [#subscription-details]

订阅的各项管理都在 Billing 页进入的 Stripe 客户门户中完成。每个账号只能有一份订阅，切换付款周期、恢复订阅都是在原有订阅上修改，不需要重新购买。

### 切换月付与年付

切换只改变付款的周期，不会带来新的额度。本周期已经用掉的额度原样保留，下一次重置的时间按切换后的付款周期重新计算，可以用 `cdg auth status{:sh}` 查看。

### 取消与恢复

取消要到当前付款周期结束时才生效。在此之前订阅仍然有效，剩余额度照常可用，`cdg auth status{:sh}` 会多出一行订阅结束的时间；结束之前也可以随时恢复订阅。年付的订阅取消后同样用到这一年结束，其间额度仍按月发放。订阅结束之后账号就没有可用订阅了，新的提交和排队中工作流的开始执行都会被拦下，见[额度不足或无订阅时](#insufficient-credits)。

### 退款 [#refunds]

已付的订阅费用原则上不退款，例外只有重复扣费、计费故障和法律要求退款的情形。取消订阅只是停止之后的续费，不退还当前付款周期的费用；年付的订阅中途取消，剩余的月份也不按比例退款。这与工作流扣除的额度是两回事：额度不会因为任务失败而自动退回，如果是 CodeDAG 自身的问题导致工作流没能正常执行，确认后会人工补回额度。申请方式与细则见[退款政策](/zh/refund)。

### 续费扣款失败

续费没有扣款成功时，订阅暂时不可用，控制台显示订阅状态为 `Past due`。这期间 CodeDAG 按没有订阅处理：提交会被拒绝，排队中的工作流开始执行时会停在 `on-hold`。在客户门户中更新支付方式、付款成功之后，订阅恢复可用，再用 `cdg dag recover{:sh}` 让被拦下的工作流继续。

### 付款后的短暂延迟

付款完成后，订阅通常要几秒钟才会生效。在这之前，`cdg dag submit{:sh}` 和 `cdg auth status{:sh}` 仍可能提示没有可用订阅，稍等片刻再试即可。

### 发票

付款记录与发票在 Stripe 客户门户中查看。

## 已知限制 [#limitations]

- **没有额度补充包。** 订阅的当月额度用完后，这个账号要等下一次重置。
- **没有团队共享额度。** 额度属于单个账号，没有供团队或组织共用的额度池；同一账号在多台电脑上使用时，共用的是这个账号自己的一份额度。
- **控制台只有英文界面。** 日期按 UTC 显示。
- **Usage 页只显示最近 20 条扣费记录。** 目前不能导出用量记录。
