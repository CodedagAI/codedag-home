CodeDAG を使うには、CodeDAG アカウントへのログインが必要です。ログインはブラウザーで Google アカウントを使って行い、アカウントは初回のログイン時に作成されます。ログインの目的は、どのアカウントがワークフローを投入しているのか、そのアカウントにクレジットがどれだけ残っているのかを確認することだけで、ワークフローはこれまでどおり自分のコンピューターで実行されます。CodeDAG サービスが受け取るのは、クレジットの計算に必要なワークフローファイルと少量の環境情報だけです。コードやログは受け取りません。

## ログインが必要な理由 [#why-sign-in]

CodeDAG は、タスク数に応じて CodeDAG クレジットを消費します。ログインは、どのアカウントがワークフローを投入しているのか、そのアカウントにクレジットがどれだけ残っているのかを確認するためのものです。ワークフロー自体はこれまでどおり自分のコンピューターで実行され、ログインしても実行がクラウドに移ることはありません。

ログインが必要なのは、次の 3 つのコマンドだけです。

| コマンド | ログインが必要な理由 |
|---|---|
| `cdg init{:sh}` | リポジトリで CodeDAG を使い始めるときに、アカウントを確認します。 |
| `cdg dag submit{:sh}` | 投入時に、クレジットが足りるかどうかを確認します。ワークフローの実行が始まるときには、タスク数に応じてクレジットを差し引きます。 |
| `cdg auth status{:sh}` | ログイン中のアカウント、サブスクリプションのステータス、クレジットの利用状況を表示します。 |

これら 3 つのコマンドは、まだログインしていないことがわかると、先にログインの手続きへ案内し、ログインが済むと元のコマンドの処理を続けます。そのため、初めて使う前にわざわざ `cdg auth login{:sh}` を実行しておく必要はありません。

## ログインする [#sign-in]

```bash title="Terminal"
cdg auth login
```

このコマンドは、今使っているコンピューターでブラウザーを開きます。現在対応しているのは、Google アカウントでのログインだけです。ある Google アカウントで初めてログインすると、CodeDAG は同時にそのアカウント用の CodeDAG アカウントを作成します。新しいアカウントには、登録時に無料クレジットが付与されます。クレジット数と有効期間は[無料クレジット](/ja/docs/account/credits-and-subscription#free-credits)を参照してください。このブラウザーですでに CodeDAG の Web コンソールにログインしている場合は、Web 側のアカウントがそのまま使われます。

### ログインが完了しなかった場合 [#sign-in-failed]

ログインがタイムアウトした、ブラウザーでキャンセルした、CodeDAG サービスに接続できなかった、といった場合は、もう一度実行してください。`cdg init{:sh}` または `cdg dag submit{:sh}` からログインが始まっていた場合は、元のコマンドも一緒に終了します。`.codedag` は作成されず、ワークフローがキューに追加されることもありません。何度も失敗する場合は、トラブルシューティングの[ログインの問題](/ja/docs/troubleshooting/troubleshooting#sign-in-problems)に沿って原因を調べてください。

### デスクトップのブラウザーがない場合 [#no-browser]

SSH のリモートセッション、コンテナー、GUI のないサーバーでは、現在のところログインできません。そのため、ログインが必要な `cdg init{:sh}` と `cdg dag submit{:sh}` も使えません。

これはログインの仕組みによるものです。ブラウザーでログインを済ませると、ブラウザーはその結果を、同じコンピューター上で待機している CLI に返します。そのため、ブラウザーと CLI は同じコンピューター上になければなりません。次の 2 つの回避策は、どちらも使えません。

- **ログイン用のリンクを別のコンピューターで開く。** そのコンピューターのブラウザーからは、結果を待っている CLI が見つからないため、ログインを完了できません。
- **別のコンピューターでログインし、認証情報をコピーしてくる。** コピーした認証情報が一度でも使われると、そのアカウントの CLI ログインは、すべてのコンピューターで無効になります。

リモートサーバーのようにブラウザーのない環境でのログインと CodeDAG の利用は、今後のバージョンで対応する計画に入っています。

## ログイン状態の有効期間 [#credentials]

このコンピューターでのログイン状態は、90 日間有効です。ワークフローを投入したりアカウントの状態を確認したりするたびに、その時点から改めて 90 日間となるため、普段から使っているコンピューターでは、ログインし直す必要はほとんどありません。

有効期間が切れると、ログインが必要なコマンドは、初回と同じようにログインを求めます。キューで待っていてまだ始まっていないワークフローは、実行の順番が来たところで `on-hold` で止まります。ログインし直してから `cdg dag recover <名前>{:sh}` を実行すれば、続行できます。

## ログアウト、複数のコンピューター、アカウントの切り替え [#sign-out]

```bash title="Terminal"
cdg auth logout
```

ログアウトで終了するのは、このコンピューターでの CLI のログインだけです。CLI のログインと Web コンソール（app.codedag.com）のログインは、互いに独立しています。Web でログアウトしても CLI はログアウトされず、CLI でログアウトしても Web やほかのコンピューターには影響しません。

ログインはコンピューターごとに 1 回ずつ必要で、同じアカウントを使うすべてのコンピューターが同じクレジットを共有します。認証情報をコピーして、コンピューター間でログイン状態を共有することはできません。コピーした認証情報がもう一度使われると、そのアカウントの CLI ログインはすべてのコンピューターで無効になり、1 台ずつログインし直す必要があります。

アカウントを切り替えるには、`cdg auth logout{:sh}` を実行してから `cdg auth login{:sh}` を実行し、別の Google アカウントを選びます。ブラウザーの Web コンソールが元のアカウントでログインしたままになっている場合は、先に Web でログアウトしてください。そうしないと、ログインには元のアカウントがそのまま使われます。

ログアウトもアカウントの切り替えも、すでに実行が始まっているワークフローには影響しません。キューで待っていてまだ始まっていないワークフローは、実行の順番が来た時点で初めて、このコンピューターのログイン状態を使います。その時点でログインしていないか、投入したときとは別のアカウントでログインしていると、ワークフローは `on-hold` で止まります。ログインし直すか元のアカウントに切り替えてから `cdg dag recover <名前>{:sh}` を実行すれば、続行できます。

## 送信されるデータの範囲 [#data-boundary]

ワークフローは自分のコンピューターで実行されます。CodeDAG サービスが受け取るのは、クレジットの計算に必要なワークフローファイルと少量の環境情報だけで、コードやログは受け取りません。

ログイン時とアカウントの照会時にやり取りするアカウント情報を除けば、CLI が CodeDAG サービスにデータを送信するのは、ワークフローを投入するときと、ワークフローの実行が始まるときだけです。送信する内容は次のとおりです。

- ワークフローファイルの内容全体と、リポジトリ内での相対パス、ファイル形式
- 今回実行するタスクの ID
- CLI のバージョン、OS、プロセッサーのアーキテクチャ

ワークフローファイルの内容とパスは、その回のクレジットを計算するためだけに使われ、計算が終わるとすぐに破棄されます。CodeDAG サービスには保存されません。課金記録に残るのは、タスク ID、CLI のバージョン、OS、プロセッサーのアーキテクチャと、ファイル内容のチェックサムだけです。チェックサムからファイルの内容を復元することはできません。

リポジトリ内のコードやその他のファイル、タスクの実行ログ、タスクエージェントのセッションの内容と成果物は、すべて自分のコンピューターに残り、CodeDAG には送信されません。タスクの実行中、Claude Code や Codex は、普段直接使うときと同じように、コードとコンテキストをそれぞれが接続しているモデルサービスに送信します。このデータは CodeDAG を経由せず、それぞれのサービスの規約に従って扱われます。

プロンプトはワークフローファイルの一部なので、ファイルと一緒にアップロードされます。シークレットや社内のアドレスなど、外部に出すべきでない情報がタスクに必要な場合は、ローカルのファイルに置き、どのファイルを読むかをプロンプトでエージェントに指示します。こうすれば、アップロードされるのはファイルのパスだけで、ファイルの内容は含まれません。

CodeDAG は、アカウントを識別するために、使用している Google アカウントの氏名、メールアドレス、プロフィール画像を記録します。データの取り扱いに関する詳しい説明は、[プライバシーポリシー](/ja/privacy)を参照してください。

## サービスを利用できない場合 [#service-unavailable]

CodeDAG サービスに一時的に接続できない場合でも、ログインが不要なコマンドと、すでに実行中のワークフローは、通常はそのまま動作します。ログイン済みのコンピューターでは、`cdg init{:sh}` による初期化も通常どおり行えます。影響を受けるのは次の項目です。

- `cdg auth login{:sh}` と `cdg auth status{:sh}` は失敗します。
- `cdg dag submit{:sh}` は失敗し、ワークフローはキューに入りません。サービスに接続できるようになってから、もう一度投入してください。
- キューで待っているワークフローは、実行の順番が来てもクレジットを差し引けないため `on-hold` で止まり、原因として `startup-gate-blocked` が表示されます。サービスに接続できるようになってから `cdg dag recover <名前>{:sh}` を実行すると、クレジットが差し引かれて実行が始まります。

すでに実行中のワークフローも、サービスに接続できない間に、コンピューターの再起動などで実行を復旧する必要が生じた場合は、`on-hold` で止まります。対処方法は同じです。
