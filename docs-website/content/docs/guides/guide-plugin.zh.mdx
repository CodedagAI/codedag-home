## 插件是什么 [#what-it-is]

CodeDAG Guide 插件为 Claude Code 和 Codex 装上一份使用 CodeDAG 的技能 `codedag-guide`。装好之后，你用自然语言描述目标，Agent 就能自己拆分任务、写出工作流文件，再用 `cdg` 校验、提交、跟踪进度和推进审核，替你完成编排，用法见[让 Agent 帮你编排](/zh/docs/get-started/let-your-agent-orchestrate)。

插件发布在 GitHub 仓库 `CodedagAI/codedag-plugin-marketplace` 中。这个仓库在 Claude Code 和 Codex 里都添加为名为 `codedag` 的 marketplace，插件在两家 Agent 里的标识都是 `codedag@codedag`。安装和更新时，由 Claude Code、Codex 自己从这个仓库取得插件；日常用 `cdg plugin{:sh}` 管理，它替你调用两家 Agent 各自的插件命令，一条命令就能处理两家。插件与 CLI 分开发布，各自更新。

## 安装插件 [#install]

在项目里初始化 CodeDAG 时，就可以顺带装好插件：

```bash title="Terminal"
cdg init
```

初始化过程中，命令为这台电脑上装着的每个 Agent 询问一次是否安装插件；已经装过插件的 Agent 则不再询问。下面是询问 Claude Code 的那一次（Codex 的选项与它基本相同）：

```bash title="Terminal"
? Install the CodeDAG plugin for Claude Code?
  Choose which Claude Code settings enable it. …
❯ 1. User-level (Claude Code user settings — applies to all your projects)
  2. Project-level (shared with your team through .claude/settings.json)
  3. Local (.claude/settings.local.json — ignored by Git; linked worktrees share the main worktree's file)
  4. Skip (install later with `cdg plugin install --claude --scope user|project|local` or Claude Code native plugin install)
```

前三项是三种安装范围，推荐直接选 `1. User-level`；选 Skip 则暂不安装。

初始化时跳过了，或者之后才装了另一个 Agent，就用下面的命令补装：

```bash title="Terminal"
cdg plugin install
```

它为本机装着的每个 Agent 把插件装在默认的 User 范围；已经装过插件的 Agent 则跳过。

插件只在新会话中生效。安装之前就开着的 Claude Code 或 Codex 会话看不到它，这些会话退出之后用 `claude --resume{:sh}` 或 `codex resume{:sh}` 恢复，就能在原来的对话里接着用。

### 选择安装范围 [#scopes]

插件默认装在 User 范围，对这台电脑上的所有仓库生效：装一次，所有仓库里的会话都能用。此外还有 Project 和 Local 两种范围，前者随仓库共享给团队，后者只在这台电脑上生效。多数情况下直接用默认的 User 范围即可。

要装在 Project 或 Local 范围，安装时用 `--scope` 指定；只为其中一个 Agent 安装时，加 `--claude` 或 `--codex`：

```bash title="Terminal"
# 只为 Claude Code 安装，Project 范围
cdg plugin install --claude --scope project
```

这两种范围各自要提交或忽略哪些文件、在多个 worktree 里怎样生效，见插件参考的[安装范围](/zh/docs/reference/cli/plugin#scopes)。

## 查看安装状态 [#status]

想确认插件装没装好、装在哪个范围，在你使用 Agent 的仓库里运行 `cdg plugin status{:sh}`。它为每个 Agent 输出一组状态，包括是否安装（`Plugin installed`）、安装范围（`Scope`）、是否启用（`Enabled`），以及安装是否完好、是否落后于 Agent 已知的最新版本（`Sync`），最后一行 `Action` 给出下一步：显示 `No action needed` 时什么也不用做，否则照它给出的命令执行。只想看一个 Agent 时，加 `--claude` 或 `--codex`。

在哪个目录运行会影响结果。User 范围的安装在任何目录都能看到，Project 和 Local 范围的安装只有在对应的仓库里运行时才看得到，所以在别的目录看到 `Plugin installed: false`，并不代表这个仓库里没有装。

`cdg plugin status{:sh}` 不联网，它拿已安装的插件与 Agent 本地保存的那份插件仓库比较。GitHub 上已经发布了新版本、而 Agent 还没刷新这份本地副本时，它照样显示 `Sync: up to date`。想确保用的是最新版本，直接运行 [`cdg plugin update`](#update)。

## 更新插件 [#update]

运行 `cdg plugin update{:sh}`，CodeDAG 先让 Agent 从 GitHub 取回插件仓库的最新内容，再把已安装的插件更新到最新版本。它默认处理本机装有的所有 Agent，加 `--claude` 或 `--codex` 只更新其中一个。更新在插件原来的范围内进行，也保留你在 Agent 里的启用或停用选择；更新之后的插件同样只在新会话中生效。

```bash title="Terminal"
cdg plugin update
```

Codex 的更新以整个 `codedag` marketplace 为单位，你从这个 marketplace 装的其他插件也会一起更新，命令会逐个列出更新了哪些插件。

两家 Agent 自己也会更新插件，只是做法不同。Codex 每次启动时都会在后台刷新从 Git 仓库添加的 marketplace，有变化的插件随之重装，所以 Codex 里的插件通常不用你手动更新。Claude Code 默认不自动更新这个 marketplace：你可以隔一段时间运行一次 `cdg plugin update{:sh}`；也可以在 Claude Code 会话里运行 `/plugin`，在 Marketplaces 标签页选中 `codedag`，再选 Enable auto-update，之后每次会话启动，Claude Code 都会自动更新插件。升级 CLI 之后也适合更新一次，原因见[升级 CLI 之后，要不要更新插件](#after-cli-upgrade)。

### 按自己的习惯定制编排 [#customize]

想让 Agent 按你的习惯编排，例如默认用哪一档授权、在哪类任务之后安排人工审核，把这些要求写进项目的 CLAUDE.md（Claude Code）或 AGENTS.md（Codex），避免直接修改插件的技能文件。这是因为写在 CLAUDE.md 或 AGENTS.md 里的要求不受插件更新影响，还能随仓库共享给团队；而改了技能文件，每次更新都要在保留修改与换成新版本之间二选一，想留下的修改还得手动迁走。

如果已经直接改过技能文件，更新时要考虑两件事：

- **更新默认保留你的修改：** 在终端里运行 `cdg plugin update{:sh}` 时，命令先问你是否备份这些文件、换回发布的内容，默认不换。由 Agent 或脚本运行时，命令不询问，直接保留修改，这个插件这次就不更新；对 Codex 来说，整个 `codedag` marketplace 这次都不更新。
- **确定不再需要这些修改时：** 先把还想留下的要求挪进 CLAUDE.md 或 AGENTS.md，再加上 `--reset-local-changes` 运行更新：

  ```bash title="Terminal"
  cdg plugin update --reset-local-changes
  ```

  命令不再询问，先把修改过的插件备份一份，再把它换成插件仓库中最新发布的内容。即使插件没有新版本，修改过的文件也会立即换回发布时的样子。备份放在哪里，见 [--reset-local-changes](/zh/docs/reference/cli/plugin#reset-local-changes)。

## 更换安装范围或卸载 [#change-scope]

要换范围，先运行 `cdg plugin uninstall{:sh}` 卸载（Project 或 Local 范围的插件要在装有它的仓库里卸载；只处理一个 Agent 时加 `--claude` 或 `--codex`），再用新的 `--scope` 安装，最后开一个新会话。只想卸载时，做第一步就够了。已安装的插件不能直接换范围：对它再运行一次 `cdg plugin install --scope <范围>{:sh}`，命令只会提示插件已经装在某个范围，然后跳过。

卸载命令没有 `--scope` 选项，会清除在当前位置能看到的所有安装，在仓库里运行时也包括 User 范围的安装。从 Project 范围卸载会改动受版本管理的配置文件，这次改动同样要提交。在哪个目录运行会清除哪些安装、团队用 Project 范围时怎样只对自己停用，以及 Local 范围卸载后留下的文件怎样处理，见 [cdg plugin uninstall](/zh/docs/reference/cli/plugin#uninstall)；两个方向换范围的完整示例见[更换安装范围](/zh/docs/reference/cli/plugin#change-scope)。

## 用 Agent 自己的命令安装 [#manual-install]

插件也可以不经过 `cdg`，用 Claude Code 或 Codex 自己的插件命令安装：先把 GitHub 仓库 `CodedagAI/codedag-plugin-marketplace` 添加为 marketplace（名为 `codedag`），再从中安装 `codedag@codedag`。如果你习惯在 Agent 里统一管理所有插件，可以这样装；其他情况下，`cdg plugin install{:sh}` 一条命令就能为两家 Agent 装好。

<Tabs items={['Claude Code', 'Codex']}>
  <Tab value="Claude Code">

```bash title="Terminal"
claude plugin marketplace add CodedagAI/codedag-plugin-marketplace
claude plugin install codedag@codedag
```

第二条命令默认装在 User 范围，要装在 Project 或 Local 范围时加上 `--scope project` 或 `--scope local`。

  </Tab>
  <Tab value="Codex">

```bash title="Terminal"
codex plugin marketplace add CodedagAI/codedag-plugin-marketplace
codex plugin add codedag@codedag
```

Codex 自己的命令只能装在 User 范围，要装在 Project 或 Local 范围，用 `cdg plugin install --codex --scope project{:sh}` 或 `--scope local`。

  </Tab>
</Tabs>

和 `cdg plugin install{:sh}` 一样，装好之后要开新会话才生效。这样装的插件同样可以用 `cdg plugin status{:sh}` 查看、用 `cdg plugin update{:sh}` 更新；用 Agent 自己的入口更新时，Claude Code 运行 `claude plugin update codedag@codedag{:sh}`（装在 Project 或 Local 范围时加上对应的 `--scope`），Codex 运行 `codex plugin marketplace upgrade codedag{:sh}`。

## 常见问题

### 装好了插件，Agent 还是不会用 CodeDAG

最常见的原因是会话在安装之前就打开了。插件只在新会话中生效，所以要退出当前会话，再用 `claude --resume{:sh}` 或 `codex resume{:sh}` 恢复。

仍然不行时，在这个仓库里运行 `cdg plugin status{:sh}`，找到你正在用的那个 Agent，按最后一行 `Action` 给出的命令或入口处理即可。想知道问题出在哪里，看 `Action` 上面的几项：

- **`Plugin installed: false`：** 在这个仓库里看不到这个 Agent 的插件，可能是：
  - 插件只装给了另一个 Agent；
  - 插件以 Project 或 Local 范围装在了别的仓库里。
- **`Sync: broken`：** 安装不完好。常见的情况是团队提交了 Project 范围的配置，而你的电脑上还没装。
- **`Enabled: false`：** 插件在 Agent 里被停用了。几个范围同时存在时以哪一个为准，见[多个范围同时存在时](/zh/docs/reference/cli/plugin#multiple-scopes)。

### 升级 CLI 之后，要不要更新插件 [#after-cli-upgrade]

建议更新，但不是必须。CLI 和插件各自发布，升级 CLI 并不会同时更新插件；新版 CLI 会保留已发布插件用到的命令、参数和含义，所以插件不更新，Agent 照样能正确使用 CLI，只是不知道新版本增加的用法。升级 CLI 之后运行一次 `cdg plugin update{:sh}`，Agent 就能用上这些新用法。

反过来，插件比 CLI 新、要求更高版本的 CLI 时，`cdg init{:sh}` 和 `cdg dag submit{:sh}` 会给出警告，这时要升级的是 CLI，见[版本兼容](/zh/docs/reference/cli/plugin#compatibility)。
