## プラグインとは [#what-it-is]

CodeDAG Guide プラグインは、CodeDAG を使うためのスキル `codedag-guide` を、Claude Code と Codex に追加します。インストールしたあとは、目標を自然言語で伝えれば、エージェントが自分でタスクを分割してワークフローファイルを書き、`cdg` で検証して投入し、進捗を追ってレビューを進めるところまで、ユーザーに代わってオーケストレーションします。使い方は[エージェントにオーケストレーションを任せる](/ja/docs/get-started/let-your-agent-orchestrate)を参照してください。

プラグインのインストールとアップグレードは CodeDAG がまとめて行い、普段の管理には `cdg plugin{:sh}` を使います。プラグイン ID は、どちらのエージェントでも `codedag@codedag` です。

## プラグインをインストールする [#install]

`cdg init{:sh}` でプロジェクトを初期化するときに、このコンピューターにインストールされているエージェントごとに 1 回ずつ、プラグインをインストールするかどうかを尋ねられます。選択肢は、後述の [3 つのインストールスコープ](#scopes)に対応しています。そのときにスキップした場合や、あとからもう一方のエージェントをインストールした場合は、`cdg plugin install{:sh}` でインストールします。

```bash title="Terminal"
# このコンピューターにインストールされている Claude Code と Codex に、User スコープでインストールする
cdg plugin install

# Claude Code にだけ、Project スコープでインストールする
cdg plugin install --claude --scope project
```

`--claude` または `--codex` を付けると、どちらか一方のエージェントにだけインストールします。`--scope` ではインストールスコープを選び、デフォルトは `user` です。

プラグインは、新しいセッションでしか有効になりません。インストールする前から開いていた Claude Code や Codex のセッションからは、プラグインが見えません。いったん終了してから `claude --resume{:sh}` または `codex resume{:sh}` で再開すれば、元の会話のまま続けて使えます。

### インストールスコープを選ぶ [#scopes]

3 つのスコープの違いは、プラグインがどこで有効になるかです。個人で使う場合は、User スコープが最も手間がかかりません。一度インストールすれば、このコンピューターのすべてのリポジトリのセッションで使えます。

| スコープ | 有効になる場所 | 向いている場面 |
|---|---|---|
| `user`（デフォルト） | このコンピューターで開くすべてのリポジトリ | 個人で使う場合や、複数のリポジトリで CodeDAG を使う場合 |
| `project` | 現在の Git リポジトリ。プラグインの設定はリポジトリ内のファイルに書き込まれ、コミットするとリポジトリと一緒に共有される | このリポジトリを開くチームメンバー全員がプラグインを使えるようにしたい場合 |
| `local` | 現在のチェックアウトだけ。設定はこのコンピューターに残り、リポジトリと一緒には共有されない。CodeDAG が Git にこれらの設定を無視させる。同じリポジトリのほかの worktree や clone でも有効にならない | ほかのリポジトリやチームメンバーに影響を与えずに、1 つのリポジトリでだけ試したい場合 |

Project スコープまたは Local スコープでインストールするときは、対象のリポジトリのディレクトリでコマンドを実行します。Project スコープで共有されるのは、リポジトリ内のプラグインの設定であって、各コンピューターへのインストールではありません。ほかのメンバーは、この設定をプルしたあと、自分のコンピューターで `cdg init{:sh}` を一度実行し、案内に従ってプラグインのインストールを済ませる必要があります。そうして初めて、そのメンバーのエージェントでプラグインが有効になります。このコマンドは、新しいメンバーがプロジェクトに参加するときに、いずれにしても実行するものです。[新しいメンバーのセットアップ](/ja/docs/guides/team-sharing#onboarding)を参照してください。

どちらのスコープでも、リポジトリにプラグインの設定ファイルが書き込まれます。たとえば Claude Code では、`.claude/settings.json`（Project スコープ）または `.claude/settings.local.json`（Local スコープ）です。インストール後にすべきことは、スコープによって異なります。

- **Project スコープ：** ファイルはバージョン管理の対象なので、インストール後にリポジトリにコミットします。チームメンバーも、これによってこの設定を受け取ります。コミットせずに残しておくと、デフォルトの分離ブランチモードでは、タスクが開始前に `on-hold` で止まり、理由は `workspace-dirty` になります（[ワークスペースに未コミットの変更がある](/ja/docs/troubleshooting/troubleshooting#hold-workspace)を参照）。
- **Local スコープ：** 何もする必要はありません。インストール時に、CodeDAG が Git にこれらのファイルを無視させています。これらのファイルがすでにリポジトリにコミットされている場合は、無視ルールが効かないため、インストールはその場で失敗し、代わりに User スコープまたは Project スコープを使うよう案内されます。[Local スコープで書き込まれる無視ルール](/ja/docs/reference/cli/plugin#local-exclude)を参照してください。

## インストール状況を確認する [#status]

プラグインが正しくインストールされているか、どのスコープにインストールされているか、更新が必要かどうかを確認したいときは、エージェントを使うリポジトリで `cdg plugin status{:sh}` を実行します。エージェントごとに状態が 1 組ずつ出力され、インストール済みかどうか（`Plugin installed`）、インストールスコープ（`Scope`）、有効かどうか（`Enabled`）などが含まれます。最後の行の `Action` には、次にすべきことが示されます。`No action needed` と表示されていれば何もする必要はなく、そうでなければ、示されたコマンドを実行します。1 つのエージェントだけを確認したい場合は、`--claude` または `--codex` を付けます。すべてのフィールドの意味は、[cdg plugin status](/ja/docs/reference/cli/plugin#status) を参照してください。

どのディレクトリで実行するかによって、結果は変わります。User スコープのインストールはどのディレクトリからでも見えますが、Project スコープと Local スコープのインストールは、対応するリポジトリで実行したときにしか見えません。そのため、別のディレクトリで `Plugin installed: false` と表示されても、このリポジトリにインストールされていないとは限りません。

`Enabled` が `false` の場合、プラグインはインストールされているものの、エージェントの側で無効になっています。この場合もエージェントはプラグインを使えず、`Action` に、もう一度有効にするよう案内が表示されます。有効に戻す操作は、エージェントの側で行います。Claude Code では `claude plugin enable codedag@codedag{:sh}` を実行し、Codex ではセッションの中で `/plugins` を開きます。

## プラグインを更新する [#update]

`cdg plugin update{:sh}` を実行すると、インストール済みのプラグインが最新バージョンに更新されます。デフォルトでは、このコンピューターにインストールされているすべてのエージェントが対象です。`--claude` または `--codex` を付けると、どちらか一方だけを更新します。プラグインをまだインストールしていないエージェントに、このコマンドでプラグインがインストールされることはありません。更新はプラグインの元のスコープのまま行われ、エージェントの側で選んだ有効・無効の状態も保たれます。インストールが壊れている場合は、同じコマンドがその場で修復します。更新後のプラグインも、新しいセッションでしか有効になりません。

```bash title="Terminal"
cdg plugin update
```

更新が必要かどうかは、`cdg plugin status{:sh}` の `Action` でわかります。CLI をアップグレードしたあとは、一度確認しておくことをおすすめします。理由は [CLI をアップグレードしたあと、プラグインも更新する必要がありますか](#after-cli-upgrade)を参照してください。

プラグインのスキルファイルを直接変更していた場合、デフォルトでは、更新によってその変更が上書きされることはありません。ターミナルで実行した場合、コマンドは、変更を残すか公式の内容に置き換えるかを先に尋ねます。デフォルトは、変更を残すほうです。スクリプトやエージェントから非対話形式で実行した場合は、変更を残して、今回の更新をスキップします。これらの変更がもう必要ないとわかっている場合は、`--reset-local-changes` を付けます。コマンドは尋ねることなく、そのまま公式の内容に置き換えます。

```bash title="Terminal"
cdg plugin update --reset-local-changes
```

<Callout type="idea">
デフォルトでどのアクセスレベルを使うか、どんなタスクのあとに手動レビューを入れるかなど、エージェントに自分のやり方でオーケストレーションさせたい場合は、その要望を CLAUDE.md（Claude Code）または AGENTS.md（Codex）に書き、プラグインのスキルファイルは CodeDAG の管理に任せたままにします。スキルファイルは更新のときに新しいバージョンに置き換えられるため、そこに加えた変更は、いずれ手作業で移し替えることになります。CLAUDE.md や AGENTS.md に書いた要望は、プラグインの更新の影響を受けません。プロジェクトに置いておけば、リポジトリと一緒にチームで共有することもできます。
</Callout>

## インストールスコープを変更する、またはアンインストールする [#change-scope]

スコープを変更するには、まず `cdg plugin uninstall{:sh}` でアンインストールし、次に新しい `--scope` でインストールして、最後に新しいセッションを開きます。Project スコープまたは Local スコープのプラグインは、インストール先のリポジトリの中でアンインストールしてください。1 つのエージェントだけを対象にする場合は、`--claude` または `--codex` を付けます。アンインストールだけをしたい場合は、最初の手順だけで足ります。インストール済みのプラグインのスコープを、直接変更することはできません。インストール済みのまま、もう一度 `cdg plugin install --scope <スコープ>{:sh}` を実行しても、コマンドは、プラグインがすでにいずれかのスコープにインストールされていると表示して、スキップするだけです。

アンインストールのコマンドには `--scope` オプションがなく、実行した場所から見えるすべてのインストールが削除されます。リポジトリの中で実行すると、そのリポジトリの Project スコープと Local スコープのインストールに加えて、User スコープのインストールも一緒に削除されます。リポジトリの外で実行すると、削除されるのは User スコープのインストールだけです。Project スコープからアンインストールすると、リポジトリ内でバージョン管理されている設定ファイルが変更されます。この変更も、同じようにコミットする必要があります。スコープをどちらの方向に変更する場合についても、完全な例は[インストールスコープを変更する](/ja/docs/reference/cli/plugin#change-scope)を参照してください。

## エージェント自身のコマンドでインストールする [#manual-install]

プラグインは、`cdg` を使わずに、Claude Code や Codex 自身のプラグインコマンドでもインストールできます。まず GitHub リポジトリ `CodedagAI/codedag-plugins` をプラグインの提供元（marketplace。名前は `codedag`）として追加し、そこから `codedag@codedag` をインストールします。すべてのプラグインをエージェントの側でまとめて管理している場合は、この方法でインストールできます。それ以外の場合は、`cdg plugin install{:sh}` を 1 回実行するだけで、両方のエージェントにインストールできます。

<Tabs items={['Claude Code', 'Codex']}>
  <Tab value="Claude Code">

```bash title="Terminal"
claude plugin marketplace add CodedagAI/codedag-plugins
claude plugin install codedag@codedag
```

  </Tab>
  <Tab value="Codex">

```bash title="Terminal"
codex plugin marketplace add CodedagAI/codedag-plugins
codex plugin add codedag@codedag
```

  </Tab>
</Tabs>

`cdg plugin install{:sh}` の場合と同じく、インストールしたあとで新しいセッションを開いて初めて有効になります。

## よくある質問

### プラグインをインストールしたのに、エージェントが CodeDAG を使えない

最もよくある原因は、インストールする前からセッションを開いていたことです。プラグインは新しいセッションでしか有効にならないので、現在のセッションを終了してから、`claude --resume{:sh}` または `codex resume{:sh}` で再開してください。

それでも使えない場合は、このリポジトリで `cdg plugin status{:sh}` を実行し、使っているエージェントの下にある 2 つの項目を確認します。`Plugin installed` が `false` の場合は、プラグインがもう一方のエージェントにしかインストールされていないか、Project スコープまたは Local スコープで別のリポジトリにインストールされている可能性があります。`Action` に示されたコマンドでインストールしてください。`Enabled` が `false` の場合は、プラグインがエージェントの側で無効になっています。[インストール状況を確認する](#status)の説明に従って、有効に戻してください。

### CLI をアップグレードしたあと、プラグインも更新する必要がありますか [#after-cli-upgrade]

更新をおすすめしますが、必須ではありません。CLI とプラグインは別々にアップグレードされ、CLI をアップグレードしても、プラグインが一緒に更新されることはありません。新しいバージョンの CLI は、公開済みのプラグインが使っているコマンド、引数、オプションと、それらの意味を維持します。そのため、プラグインを更新しなくても、エージェントはこれまでどおり CLI を正しく使えます。新しいバージョンで追加された使い方を知らないだけです。CLI をアップグレードしたあとは、`cdg plugin status{:sh}` を一度実行し、`Action` の案内に従ってください。互換性のルールは、[バージョンの互換性](/ja/docs/reference/cli/plugin#compatibility)を参照してください。
