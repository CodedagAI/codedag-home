## プラグインとは [#what-it-is]

CodeDAG Guide プラグインは、CodeDAG を使うためのスキル `codedag-guide` を、Claude Code と Codex に追加します。インストールしたあとは、目標を自然言語で伝えれば、エージェントが自分でタスクを分割してワークフローファイルを書き、`cdg` で検証して投入し、進捗を追ってレビューを進めるところまで、ユーザーに代わってオーケストレーションします。使い方は[エージェントにオーケストレーションを任せる](/ja/docs/get-started/let-your-agent-orchestrate)を参照してください。

プラグインは GitHub リポジトリ `CodedagAI/codedag-plugin-marketplace` で公開されています。このリポジトリは、Claude Code と Codex のどちらにも `codedag` という名前の marketplace として追加され、プラグイン ID はどちらのエージェントでも `codedag@codedag` です。インストールや更新のときは、Claude Code と Codex がそれぞれ自分でこのリポジトリからプラグインを取得します。普段の管理には `cdg plugin{:sh}` を使います。このコマンドが両方のエージェントのプラグインコマンドを代わりに呼び出すので、1 つのコマンドで両方を扱えます。プラグインは CLI とは別にリリースされ、それぞれ個別に更新されます。

## プラグインをインストールする [#install]

プロジェクトで CodeDAG を初期化するときに、プラグインも一緒にインストールできます。

```bash title="Terminal"
cdg init
```

初期化の途中で、このコンピューターにインストールされているエージェントごとに 1 回ずつ、プラグインをインストールするかどうかを尋ねられます。すでにプラグインが入っているエージェントについては尋ねられません。Claude Code について尋ねられるときの表示は次のとおりです（Codex の選択肢もほぼ同じです）。

```bash title="Terminal"
? Install the CodeDAG plugin for Claude Code?
  Choose which Claude Code settings enable it. …
❯ 1. User-level (Claude Code user settings — applies to all your projects)
  2. Project-level (shared with your team through .claude/settings.json)
  3. Local (.claude/settings.local.json — ignored by Git; linked worktrees share the main worktree's file)
  4. Skip (install later with `cdg plugin install --claude --scope user|project|local` or Claude Code native plugin install)
```

最初の 3 つの選択肢は、3 種類のインストールスコープです。そのまま `1. User-level` を選ぶのがおすすめです。Skip を選ぶと、今はインストールしません。

初期化のときにスキップした場合や、あとからもう一方のエージェントをインストールした場合は、次のコマンドでインストールします。

```bash title="Terminal"
cdg plugin install
```

このコマンドは、このコンピューターにインストールされている各エージェントに、デフォルトの User スコープでプラグインをインストールします。すでにプラグインが入っているエージェントはスキップします。

プラグインは、新しいセッションでしか有効になりません。インストールする前から開いていた Claude Code や Codex のセッションからは、プラグインが見えません。そうしたセッションは、いったん終了してから `claude --resume{:sh}` または `codex resume{:sh}` で再開すれば、元の会話のまま続けて使えます。

### インストールスコープを選ぶ [#scopes]

プラグインは、デフォルトでは User スコープにインストールされ、このコンピューターのすべてのリポジトリで有効になります。一度インストールすれば、どのリポジトリのセッションでも使えます。ほかに Project と Local の 2 つのスコープがあり、Project はリポジトリと一緒にチームで共有され、Local はこのコンピューターでだけ有効です。たいていはデフォルトの User スコープをそのまま使えば十分です。

Project スコープまたは Local スコープにインストールするには、インストールするときに `--scope` で指定します。どちらか一方のエージェントにだけインストールする場合は、`--claude` または `--codex` を付けます。

```bash title="Terminal"
# Claude Code にだけ、Project スコープでインストールする
cdg plugin install --claude --scope project
```

この 2 つのスコープでそれぞれどのファイルをコミットまたは無視するのか、複数の worktree でどう有効になるのかは、プラグインのリファレンスの[インストールスコープ](/ja/docs/reference/cli/plugin#scopes)を参照してください。

## インストール状況を確認する [#status]

プラグインが正しくインストールされているか、どのスコープにインストールされているかを確認したいときは、エージェントを使うリポジトリで `cdg plugin status{:sh}` を実行します。エージェントごとに状態が 1 組ずつ出力され、インストール済みかどうか（`Plugin installed`）、インストールスコープ（`Scope`）、有効かどうか（`Enabled`）、インストールが壊れていないか、エージェントが把握している最新バージョンより古くなっていないか（`Sync`）が含まれます。最後の行の `Action` には、次にすべきことが示されます。`No action needed` と表示されていれば何もする必要はなく、そうでなければ、示されたコマンドを実行します。1 つのエージェントだけを確認したい場合は、`--claude` または `--codex` を付けます。

どのディレクトリで実行するかによって、結果は変わります。User スコープのインストールはどのディレクトリからでも見えますが、Project スコープと Local スコープのインストールは、対応するリポジトリで実行したときにしか見えません。そのため、別のディレクトリで `Plugin installed: false` と表示されても、このリポジトリにインストールされていないとは限りません。

`cdg plugin status{:sh}` はネットワークに接続せず、インストール済みのプラグインを、エージェントがローカルに保存しているプラグインリポジトリのコピーと比較します。GitHub で新しいバージョンが公開されていても、エージェントがこのローカルのコピーをまだ更新していなければ、`Sync: up to date` と表示されます。確実に最新バージョンを使いたい場合は、そのまま [`cdg plugin update`](#update) を実行してください。

## プラグインを更新する [#update]

`cdg plugin update{:sh}` を実行すると、CodeDAG はまずエージェントに GitHub からプラグインリポジトリの最新の内容を取得させ、そのうえでインストール済みのプラグインを最新バージョンに更新します。デフォルトでは、このコンピューターにインストールされているすべてのエージェントが対象です。`--claude` または `--codex` を付けると、どちらか一方だけを更新します。更新はプラグインの元のスコープのまま行われ、エージェントの側で選んだ有効・無効の状態も保たれます。更新後のプラグインも、新しいセッションでしか有効になりません。

```bash title="Terminal"
cdg plugin update
```

Codex の更新は `codedag` marketplace 全体が単位になるため、この marketplace からインストールしたほかのプラグインも一緒に更新されます。どのプラグインが更新されたかは、コマンドが 1 つずつ表示します。

どちらのエージェントも自分でプラグインを更新しますが、そのやり方は異なります。Codex は起動するたびに、Git リポジトリから追加した marketplace をバックグラウンドで更新し、変更のあったプラグインを入れ直します。そのため、Codex のプラグインは通常、手動で更新する必要はありません。Claude Code は、デフォルトではこの marketplace を自動更新しません。ときどき `cdg plugin update{:sh}` を実行するか、Claude Code のセッションで `/plugin` を実行し、Marketplaces タブで `codedag` を選んでから Enable auto-update を選びます。そうすれば、以降はセッションを開始するたびに、Claude Code がプラグインを自動で更新します。CLI をアップグレードしたあとも、一度更新しておくとよいでしょう。理由は [CLI をアップグレードしたあと、プラグインも更新する必要がありますか](#after-cli-upgrade)を参照してください。

### 自分のやり方に合わせてオーケストレーションをカスタマイズする [#customize]

デフォルトでどのアクセスレベルを使うか、どんなタスクのあとに手動レビューを入れるかなど、エージェントに自分のやり方でオーケストレーションさせたい場合は、その要望をプロジェクトの CLAUDE.md（Claude Code）または AGENTS.md（Codex）に書き、プラグインのスキルファイルを直接変更するのは避けてください。CLAUDE.md や AGENTS.md に書いた要望はプラグインの更新の影響を受けず、リポジトリと一緒にチームで共有することもできるからです。一方、スキルファイルを変更すると、更新のたびに、変更を残すか新しいバージョンに置き換えるかを選ぶことになり、残したい変更は手作業で移し替えなければなりません。

すでにスキルファイルを直接変更している場合は、更新するときに次の 2 点に注意してください。

- **更新は、デフォルトでは変更を残します：** ターミナルで `cdg plugin update{:sh}` を実行した場合、コマンドは、それらのファイルをバックアップして公開時の内容に戻すかどうかを先に尋ねます。デフォルトは、戻さないほうです。エージェントやスクリプトから実行した場合は、尋ねずにそのまま変更を残し、このプラグインは今回更新されません。Codex では、今回は `codedag` marketplace 全体が更新されません。
- **これらの変更がもう必要ないとわかっている場合：** 残しておきたい要望を先に CLAUDE.md や AGENTS.md に移してから、`--reset-local-changes` を付けて更新します。

  ```bash title="Terminal"
  cdg plugin update --reset-local-changes
  ```

  コマンドは尋ねることなく、変更されたプラグインのバックアップを取ってから、プラグインリポジトリで公開されている最新の内容に置き換えます。プラグインに新しいバージョンがない場合も、変更したファイルはすぐに公開時の状態に戻ります。バックアップの場所は、[--reset-local-changes](/ja/docs/reference/cli/plugin#reset-local-changes) を参照してください。

## インストールスコープを変更する、またはアンインストールする [#change-scope]

スコープを変更するには、まず `cdg plugin uninstall{:sh}` でアンインストールし、次に新しい `--scope` でインストールして、最後に新しいセッションを開きます。Project スコープまたは Local スコープのプラグインは、インストール先のリポジトリの中でアンインストールしてください。1 つのエージェントだけを対象にする場合は、`--claude` または `--codex` を付けます。アンインストールだけをしたい場合は、最初の手順だけで足ります。インストール済みのプラグインのスコープを、直接変更することはできません。インストール済みのまま、もう一度 `cdg plugin install --scope <スコープ>{:sh}` を実行しても、コマンドは、プラグインがすでにいずれかのスコープにインストールされていると表示して、スキップするだけです。

アンインストールのコマンドには `--scope` オプションがなく、実行した場所から見えるすべてのインストールが削除されます。リポジトリの中で実行した場合は、User スコープのインストールも含まれます。Project スコープからアンインストールすると、バージョン管理されている設定ファイルが変更されるので、この変更も同じようにコミットする必要があります。どのディレクトリで実行するとどのインストールが削除されるか、チームで Project スコープを使っているときに自分だけ無効にする方法、Local スコープのアンインストール後に残るファイルをどう扱うかは、[cdg plugin uninstall](/ja/docs/reference/cli/plugin#uninstall) を参照してください。スコープをどちらの方向に変更する場合についても、完全な例は[インストールスコープを変更する](/ja/docs/reference/cli/plugin#change-scope)を参照してください。

## エージェント自身のコマンドでインストールする [#manual-install]

プラグインは、`cdg` を使わずに、Claude Code や Codex 自身のプラグインコマンドでもインストールできます。まず GitHub リポジトリ `CodedagAI/codedag-plugin-marketplace` を marketplace（名前は `codedag`）として追加し、そこから `codedag@codedag` をインストールします。すべてのプラグインをエージェントの側でまとめて管理している場合は、この方法でインストールできます。それ以外の場合は、`cdg plugin install{:sh}` を 1 回実行するだけで、両方のエージェントにインストールできます。

<Tabs items={['Claude Code', 'Codex']}>
  <Tab value="Claude Code">

```bash title="Terminal"
claude plugin marketplace add CodedagAI/codedag-plugin-marketplace
claude plugin install codedag@codedag
```

2 つ目のコマンドは、デフォルトでは User スコープにインストールします。Project スコープまたは Local スコープにインストールする場合は、`--scope project` または `--scope local` を付けます。

  </Tab>
  <Tab value="Codex">

```bash title="Terminal"
codex plugin marketplace add CodedagAI/codedag-plugin-marketplace
codex plugin add codedag@codedag
```

Codex 自身のコマンドでインストールできるのは User スコープだけです。Project スコープまたは Local スコープにインストールする場合は、`cdg plugin install --codex --scope project{:sh}` または `--scope local` を使います。

  </Tab>
</Tabs>

`cdg plugin install{:sh}` の場合と同じく、インストールしたあとで新しいセッションを開いて初めて有効になります。この方法でインストールしたプラグインも、`cdg plugin status{:sh}` で確認し、`cdg plugin update{:sh}` で更新できます。エージェント自身の方法で更新する場合、Claude Code では `claude plugin update codedag@codedag{:sh}` を実行し（Project スコープまたは Local スコープにインストールした場合は、対応する `--scope` を付けます）、Codex では `codex plugin marketplace upgrade codedag{:sh}` を実行します。

## よくある質問

### プラグインをインストールしたのに、エージェントが CodeDAG を使えない

最もよくある原因は、インストールする前からセッションを開いていたことです。プラグインは新しいセッションでしか有効にならないので、現在のセッションを終了してから、`claude --resume{:sh}` または `codex resume{:sh}` で再開してください。

それでも使えない場合は、このリポジトリで `cdg plugin status{:sh}` を実行し、使っているエージェントの出力を見て、最後の行の `Action` に示されたコマンドや操作に従って対処してください。どこに問題があるのかを知りたい場合は、`Action` の上にある項目を確認します。

- **`Plugin installed: false`：** このリポジトリからは、このエージェントのプラグインが見えません。次の可能性があります。
  - プラグインがもう一方のエージェントにしかインストールされていない。
  - プラグインが Project スコープまたは Local スコープで別のリポジトリにインストールされている。
- **`Sync: broken`：** インストールが壊れています。よくあるのは、チームが Project スコープの設定をコミットしたのに、自分のコンピューターにはまだインストールされていない場合です。
- **`Enabled: false`：** プラグインがエージェントの側で無効になっています。複数のスコープが同時にあるときにどのスコープの設定が使われるかは、[複数のスコープが同時にある場合](/ja/docs/reference/cli/plugin#multiple-scopes)を参照してください。

### CLI をアップグレードしたあと、プラグインも更新する必要がありますか [#after-cli-upgrade]

更新をおすすめしますが、必須ではありません。CLI とプラグインは別々にリリースされ、CLI をアップグレードしても、プラグインが一緒に更新されることはありません。新しいバージョンの CLI は、公開済みのプラグインが使っているコマンド、引数、オプションと、それらの意味を維持します。そのため、プラグインを更新しなくても、エージェントはこれまでどおり CLI を正しく使えます。新しいバージョンで追加された使い方を知らないだけです。CLI をアップグレードしたあとに `cdg plugin update{:sh}` を一度実行すれば、エージェントがそうした新しい使い方も使えるようになります。

逆に、プラグインのほうが CLI より新しく、より新しいバージョンの CLI を必要とする場合は、`cdg init{:sh}` と `cdg dag submit{:sh}` が警告を表示します。このときアップグレードが必要なのは CLI のほうです。[バージョンの互換性](/ja/docs/reference/cli/plugin#compatibility)を参照してください。
