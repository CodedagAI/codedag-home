`cdg plugin{:sh}` には `install`、`status`、`update`、`uninstall` の 4 つのサブコマンドがあり、それぞれ CodeDAG Guide プラグインのインストール、状況の確認、更新、アンインストールに使います。プラグインは GitHub リポジトリ `CodedagAI/codedag-plugin-marketplace` で公開されています。このリポジトリは、Claude Code と Codex のどちらにも `codedag` という名前の marketplace として追加され、プラグイン ID はどちらのエージェントでも `codedag@codedag` です。これらのコマンドは、どれもログインを必要とせず、現在のディレクトリが `cdg init{:sh}` で初期化済みのプロジェクトである必要もありません。プラグインでできることと普段の管理方法は、[CodeDAG Guide プラグインを管理する](/ja/docs/guides/guide-plugin)を参照してください。

インストールと更新が有効になるのは、そのあとに新しく開いたエージェントセッションだけです。すでに開いているセッションで新しいプラグインを使うには、いったん終了してから、`claude --resume{:sh}` または `codex resume{:sh}` で再開します。

## 対象のエージェントを選ぶ [#targets]

4 つのサブコマンドは、どれも次のオプションで、どのエージェントのプラグインを対象にするかを選びます。

| オプション | どのエージェントのプラグインが対象になるか |
|---|---|
| `--claude` | Claude Code |
| `--codex` | Codex |
| `-a`、`--all` | Claude Code と Codex |
| 省略 | `--all` と同じ |

オプションを省略した場合と `--all` を指定した場合、`install` と `update` は、このコンピューターにインストールされているエージェントだけを処理します。

## cdg plugin install [#install]

```bash title="Terminal"
cdg plugin install [--claude | --codex | --all] [-s <スコープ>]
```

`cdg plugin install{:sh}` は、対象のエージェントにプラグインをインストールします。エージェントに `codedag` marketplace がまだない場合は、先に追加します。インストールスコープは `-s` / `--scope` で指定します。値は `user`、`project`、`local` のいずれかで、デフォルトは `user` です。スコープごとの違いは、[インストールスコープ](#scopes)を参照してください。`user` スコープは、どのディレクトリからでもインストールできます。一方、`project` と `local` はコマンドを実行したチェックアウトにインストールされるため、Git リポジトリの中で実行する必要があります。

```bash title="Terminal"
# このコンピューターにインストールされているすべてのエージェントに、User スコープでインストールする
cdg plugin install
# Claude Code にだけ、Local スコープでインストールする
cdg plugin install --claude -s local
```

プラグインがすでにインストールされている場合、`install` は再インストールもスコープの変更もしません。現在の場所からそのエージェントのプラグインが見えていれば、どのスコープにインストールされているかにかかわらず、コマンドはそのままスキップします。たとえば、User スコープでインストールしたあとは、どのリポジトリで `cdg plugin install --scope project{:sh}` を実行しても効果はありません。スコープを変更する方法は、[インストールスコープを変更する](#change-scope)を参照してください。

## インストールスコープ [#scopes]

CodeDAG でプラグインをインストールするときは、Claude Code と Codex のどちらでも User、Project、Local の 3 つのスコープから選べます。デフォルトは User です。3 つのスコープの違いは、プラグインを有効にする設定がどこに書き込まれるかにあり、それによって、プラグインがどこで有効になるか、リポジトリと一緒に共有されるかどうかが決まります。

| スコープ | 有効になる場所 | 設定の書き込み先 | 向いている場面 |
|---|---|---|---|
| `user`（デフォルト） | このコンピューターのすべてのリポジトリとレプリカ | ホームディレクトリにある Claude Code または Codex の設定。どのリポジトリにも書き込まれません | 個人で使う場合や、複数のリポジトリで CodeDAG を使う場合 |
| `project` | このリポジトリ。設定をコミットすると、リポジトリと一緒にチームで共有されます | 現在のチェックアウトにある、バージョン管理の対象の `.claude/settings.json` または `.codex/config.toml`。Claude Code のこのファイルには、`codedag` marketplace をどのリポジトリから取得するかも書き込まれます | このリポジトリを開くチームメンバー全員がプラグインを使えるようにしたい場合 |
| `local` | 現在のチェックアウト。Claude Code では、同じリポジトリのほかの worktree も含みます。リポジトリと一緒には共有されません | Git に無視される `.claude/settings.local.json` または `.codex/config.toml` | ほかのリポジトリやチームメンバーに影響を与えずに、1 つのリポジトリでだけ試したい場合。Codex では、リポジトリに `.codex/config.toml` がコミットされていないことが条件です |

Codex の Project スコープと Local スコープは、同じ `.codex/config.toml` に書き込みます。違いは、このファイルをリポジトリにコミットするか、Git に無視させるかです。CodeDAG がこのファイルで追加・削除するのはプラグインの項目だけなので、ファイルに自分で書いたほかの Codex の設定はそのまま残ります。

### Project スコープ [#project-scope]

Project スコープの設定は、プロジェクトリポジトリと一緒に共有されます。ほかのメンバーがプルしてから `cdg init{:sh}` を実行すると、CodeDAG はこの設定に従ってプラグインをインストールし、スコープを尋ねることはありません。[新しいメンバーのセットアップ](/ja/docs/guides/team-sharing#onboarding)を参照してください。

`cdg init{:sh}` を実行済みのメンバーは、通常は何もする必要はありません。ただし、次の 2 つの場合は、もう少し対処が必要です。

- **初期化のときに、プラグインのインストールをスキップした場合**
- **Claude Code を使っていて、同じコンピューターにリポジトリをもう 1 つ clone した場合：** Claude Code は Project スコープのインストールをチェックアウトごとに登録するため、元のチェックアウトでのインストールは新しい clone には含まれません。一方、Codex のプラグインのインストールはこのコンピューターのすべてのプロジェクトで共有されるため、Codex では新しい clone でインストールし直す必要はありません。

どちらの場合も、`cdg plugin status{:sh}` には `Sync: broken` と表示されます。`cdg plugin update{:sh}` を実行すれば、インストールされます。

### Local スコープ [#local-exclude]

Local スコープの設定は Git に無視されるファイルに書き込まれるため、このコンピューターでだけ有効です。無視ルールは、インストールのときに CodeDAG がリポジトリの `info/exclude`（通常のリポジトリでは `.git/info/exclude`）に書き込みます。これはこのコンピューターでだけ効く Git の無視ファイルなので、Local スコープをインストールするために、チームで共有している `.gitignore` を変更する必要はありません。書き込まれるファイルは、エージェントによって異なります。

- **Claude Code：** Claude Code ネイティブの Local スコープを使い、有効化の項目を `.claude/settings.local.json` に書き込みます。
- **Codex：** Codex は Local スコープをネイティブにはサポートしていないため、CodeDAG が有効化の項目をプロジェクトの `.codex/config.toml` に書き込み、ファイル全体を Git に無視させます。そのため、このファイルに自分で書いたほかの Codex の設定も、このコンピューターでだけ有効になります。

Codex の Local スコープが向いているのは、個人のプロジェクトと、`.codex/config.toml` をコミットしないとチームで決めている（`.gitignore` に記載済みの）リポジトリの 2 種類です。Codex の Local スコープはファイル全体を Git に無視させるため、このファイルが Git に追跡されていないリポジトリにしかインストールできません。Codex のプロジェクト設定をすでに使っているリポジトリでは、たいていこのファイルがコミットされているので、Codex では User スコープか Project スコープしか使えません。

このファイルがまだなく、コミットしないという取り決めもないチームのリポジトリに、Codex の Local スコープをインストールすることはおすすめしません。こうしたリポジトリにもインストールはできますが、あとでチームがこのファイルをコミットする可能性があります。そうなると、そのコミットをプルまたはチェックアウトしたときに、Git はエラーも警告も出さずに、ローカルのファイルをリポジトリのバージョンで上書きします。ファイルに自分で書いたほかの設定も失われます。こうしたリポジトリにすでにインストールしている場合は、次のように対処できます。

- **User スコープに切り替える：** User スコープはリポジトリにファイルを一切書き込まないため、上書きされることもありません。手順は[インストールスコープを変更する](#change-scope)を参照してください。
- **このファイルをコミットしないとチームで決める：** `.codex/config.toml` を `.gitignore` に書けば、このリポジトリは、上で挙げた Local スコープに向いている種類のリポジトリになります。
- **Local スコープを使い続ける：** このファイルに自分で書いたほかの設定を別にバックアップしておき、上書きされたあとで、その設定をファイルに組み込み直します。

同じリポジトリのほかの worktree でもセッションを開く場合も、2 つのエージェントで動作が異なります。Claude Code では、各 worktree がメインの worktree にある `.claude/settings.local.json` を共有するため、一度インストールすれば、すべての worktree で有効になります。一方、Codex の Local スコープはインストールしたチェックアウトでだけ有効なので、worktree ごとにインストールする必要があります。

## cdg plugin status [#status]

```bash title="Terminal"
cdg plugin status [--claude | --codex | --all]
```

`cdg plugin status{:sh}` は、エージェントごとに状態を 1 組ずつ出力します。最後の行の `Action` に次にすべきことが示されるので、そのとおりに対処してください。出力のうち、次の 2 つは誤解しやすい項目です。

- **`Sync: up to date` は、GitHub 上の最新バージョンであることを意味しません：** このコマンドはネットワークに接続しません。`Available version` は、エージェントが最後に `codedag` marketplace を更新したときに取得したバージョンです。そのため `up to date` が示すのは、インストール済みのバージョンがこのバージョンと同じであることだけです。Claude Code はデフォルトでは marketplace を自動更新しないため、このずれは Claude Code で起こりやすくなります。確実に最新バージョンを使いたい場合は、そのまま [`cdg plugin update`](#update) を実行してください。
- **`Sync: update available, local changes` は、プラグインを変更したことを意味するとは限りません：** コマンドは、プラグインのファイルが変更されたかどうかを判断できない場合も、変更されたものとして扱います。どんなときにこうなるか、どう対処するかは、[プラグインを変更していないのに、ローカルの変更があると表示される](/ja/docs/troubleshooting/troubleshooting#plugin-local-changes)を参照してください。

### 複数のスコープが同時にある場合 [#multiple-scopes]

1 つのエージェントのプラグインが同時に複数のスコープにある場合（たとえば、自分では User スコープでインストールしていて、リポジトリにはチームがコミットした Project スコープもある場合）、`Scope` にはそれらのスコープが表示されます。`Enabled` には、現在のディレクトリで実際に使われる有効・無効の値が表示されます。このとき、Local は Project より、Project は User より優先されます。

Codex には、意外に感じやすい点が 1 つあります。`/plugins` でプラグインを無効にしたときに変わるのはユーザーレベルの設定ですが、Codex ではプロジェクトの設定がユーザーレベルの設定より優先されます。そのため、この方法で無効にしても、Project スコープや Local スコープがインストールされているプロジェクトでは効果がありません。こうしたプロジェクトで自分だけプラグインを使わないようにしたい場合は、[各スコープをアンインストールしたあと](#after-uninstall)を参照してください。

### バージョンの互換性 [#compatibility]

プラグインと CLI は別々にリリースされ、バージョン番号が一致している必要はありません。プラグインは、サポートする最低の CLI バージョンと、検証済みの CLI バージョンを宣言しています。`CLI compatibility` には、これをもとに、このコンピューターの CLI がどの段階にあたるかが表示されます。`compatible` と表示されていれば、対応は不要です。ほかの 2 つの表示は次のとおりです。

- **`CLI too old (requires <最低バージョン> or later)`：** このコンピューターの CLI が、プラグインのサポートする最低バージョンより古い状態です。[CLI をアップグレード](/ja/docs/get-started/installation)してください。そうしないと、このコンピューターの CLI がまだ対応していないコマンド、引数、オプションを、エージェントが使う可能性があります。
- **`newer than verified (verified with <検証済みバージョン>)`：** このコンピューターの CLI が、プラグインの検証済みバージョンより新しい状態です。新しいバージョンの CLI は、公開済みのプラグインが使っているコマンド、引数、オプションと、それらの意味を維持するので、対応は不要です。新しいバージョンの CLI で増えた使い方をエージェントに知らせたい場合は、プラグインを更新してください。

## cdg plugin update [#update]

```bash title="Terminal"
cdg plugin update [--claude | --codex | --all] [--reset-local-changes]
```

`cdg plugin update{:sh}` は、まずエージェントに GitHub から `codedag` marketplace を更新させ、そのうえでインストール済みのプラグインを最新バージョンに更新します。プラグインが User スコープにインストールされている場合は、どのディレクトリからでも、一度実行すれば済みます。

インストールが壊れている場合、コマンドはプラグインを修復するだけで、marketplace の更新も、最新バージョンへの更新も行いません。修復でインストールされるのは、このコンピューターにある marketplace のコピーに含まれるバージョンで、これは古くなっている可能性があります。しかも修復のあとは、`cdg plugin status{:sh}` に `up to date` と表示されることもあります。そのため、最新バージョンに更新するには、修復のあとにもう一度実行する必要があります。

Claude Code のプラグインがほかのリポジトリの Project スコープや Local スコープにインストールされている場合、そこのインストールを更新するには、そのリポジトリで一度実行する必要があります。コマンドが更新するのは、現在の場所から見えるスコープだけだからです。Codex の場合は異なります。Codex のプラグインのファイルはこのコンピューターのすべてのプロジェクトで共有されているため、インストールされているいずれかの場所で一度更新すれば、すべてのプロジェクトのインストールが更新されます。

### --reset-local-changes [#reset-local-changes]

プラグインのファイルが変更されている場合、`update` はデフォルトで変更を残し、今回はこのプラグインを更新しません。ターミナルで実行した場合は、公開時の内容に戻すかどうかをコマンドが先に尋ね、デフォルトは戻さないほうです。`--reset-local-changes` を付けると、コマンドは尋ねずに、変更されたプラグインを先にバックアップしてから、プラグインリポジトリで公開されている最新の内容に置き換えます。新しいバージョンがない場合も、変更されたファイルは公開時の状態に戻ります。

```bash title="Terminal"
cdg plugin update --reset-local-changes
```

バックアップは、CodeDAG のグローバルディレクトリ（デフォルトは `~/.codedag`）の下の `plugin-backups/claude-code/` または `plugin-backups/codex/` に置かれます。各エージェントに残るのは直近のバックアップ 1 つだけで、次にバックアップするときに上書きされます。そのため、残しておきたい変更がある場合は、早めに別の場所へ移してください。オーケストレーションについて長く残しておきたい要望は、CLAUDE.md または AGENTS.md に書くのが適しています。理由は[自分のやり方に合わせてオーケストレーションをカスタマイズする](/ja/docs/guides/guide-plugin#customize)を参照してください。

## cdg plugin uninstall [#uninstall]

```bash title="Terminal"
cdg plugin uninstall [--claude | --codex | --all]
```

`cdg plugin uninstall{:sh}` は、現在の場所から見えるすべてのインストールをアンインストールします。そのため、`--scope` オプションはありません。

### アンインストールの対象 [#uninstall-targets]

Git リポジトリの中で実行した場合に見えるのは、そのチェックアウトの Project スコープと Local スコープ、および User スコープです。リポジトリの外で実行した場合は、User スコープだけが見えます。そのため、どのインストールがアンインストールされるかは、次の 2 つの場合に分かれます。

- **User スコープだけをインストールしている場合：** どのディレクトリで実行しても、アンインストールされるのは User スコープだけで、結果は同じです。
- **このチェックアウトに Project スコープや Local スコープもインストールされている場合（チームがコミットした Project スコープを含む）：** リポジトリの中で実行すると、それらが User スコープと一緒にアンインストールされ、このコンピューターのほかのリポジトリのセッションでもプラグインを使えなくなります。User スコープだけをアンインストールしたい場合は、Git リポジトリの外のディレクトリで実行します。

### 各スコープをアンインストールしたあと [#after-uninstall]

アンインストールしたあとには、スコープごとに次のような影響もあります。

- **User スコープ：**
  - **Codex：** プラグインは無効になるだけで、プラグインのファイルはこのコンピューターに残ります。ほかのプロジェクトの Project スコープや Local スコープが、まだこのファイルを使っている可能性があるためです。ファイルまで削除するには、アンインストールの出力に示されるコマンドを実行します。
- **Project スコープ：** 変更されるのはチームで共有している設定なので、この変更をコミットすると、チーム全員の環境でプラグインが読み込まれなくなります。自分だけ使わないようにしたい場合は、リポジトリの中でアンインストールするのは避け、エージェントに応じて次の方法を使います。
  - **Claude Code：** Claude Code 自身のコマンド `claude plugin disable codedag@codedag --scope local{:sh}` で、このコンピューターでだけ無効にします。
  - **Codex：** Codex ではプロジェクトの設定がユーザーレベルの設定より優先されるため、自分だけ無効にすることはできません。どうしても使いたくない場合は、自分の `~/.codex/AGENTS.md` に、このリポジトリでは CodeDAG のプラグインを使わないと書いておきます。
- **Local スコープ：**
  - **Codex：** `.codex/config.toml` は Codex 自身の設定ファイルです。通常、アンインストールで削除されるのはプラグインの項目だけで、ファイルとほかの設定は残ります。ただし、プラグインの項目を削除するとファイルに何も残らない場合は、コマンドがファイルごと削除します。アンインストールでは CodeDAG が追加した[無視ルール](#local-exclude)も削除されるので、残ったファイルをそのあとどう扱うかは、リポジトリの種類によって決まります。
    - **このファイルをコミットしないとチームで決めているリポジトリ：** `.gitignore` によって引き続き無視されるので、対処は不要です。
    - **個人のプロジェクト：** ファイルは未追跡のファイルとして `git status` に表示されます。これがそのままこのプロジェクトの Codex の設定なので、コミットしてかまいません。コミットしたくない場合は、このファイル用の無視ルールを自分で追加します。
    - **まだこの取り決めがないチームのリポジトリ（おすすめしない使い方）：** この場合も、ファイルは `git status` に表示されます。このファイルはもう普通の Codex の設定ファイルにすぎないので、どう扱うかはチームで話し合って決めてください。
  - **Claude Code で、同じリポジトリに worktree が複数ある場合：** 各 worktree はメインの worktree にある `.claude/settings.local.json` を共有しているため、そのうち 1 つの worktree でアンインストールすると、ほかの worktree でもプラグインが無効になります。そこで引き続き使うには、その worktree で `claude plugin enable codedag@codedag --scope local{:sh}` を実行します。`--scope local` は省略できません。

## インストールスコープを変更する [#change-scope]

インストール済みのプラグインのスコープを、直接変更することはできません。まずアンインストールし、次に新しい `--scope` でインストールして、最後に新しいエージェントセッションを開きます。

2 つのコマンドは、どちらも正しい場所で実行する必要があります。アンインストールは、元のインストールが見える場所で行います。元のスコープが Project または Local の場合は、そのプラグインがインストールされているチェックアウトです。新しいスコープが Project または Local の場合は、インストールも対象のチェックアウトの中で実行します。一方のエージェントのスコープだけを変更する場合は、両方のコマンドに `--claude` または `--codex` を付けます。もう一方のエージェントのプラグインは、そのまま残ります。

次の例では、両方のエージェントのプラグインを、User スコープからリポジトリ `~/code/my-app` の Project スコープに変更します。

```bash title="Terminal"
cd ~/code/my-app
cdg plugin uninstall
cdg plugin install --scope project
```

アンインストールをリポジトリの中で実行したため、元の User スコープのインストールも一緒にアンインストールされました。そのため、このコンピューターのほかのリポジトリでは、もうこのプラグインが読み込まれません。必要な場合は、そのリポジトリで別途インストールします。新しく書き込まれた `.claude/settings.json` と `.codex/config.toml` は、プロジェクトリポジトリにコミットして初めて、チームメンバーと共有されます。

逆に、Project スコープから User スコープに戻す場合も、同じように、まずこのリポジトリの中でアンインストールし、次に `--scope user` でインストールします。このアンインストールでリポジトリ内のプロジェクトの設定が変更されるため、この変更も同じようにプロジェクトリポジトリにコミットする必要があります。
