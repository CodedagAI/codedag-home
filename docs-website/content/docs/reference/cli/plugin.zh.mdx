`cdg plugin{:sh}` 下有 `install`、`status`、`update`、`uninstall` 四个子命令，分别用来安装、查看、更新和卸载 CodeDAG Guide 插件。插件发布在 GitHub 仓库 `CodedagAI/codedag-plugin-marketplace`。这个仓库在 Claude Code 和 Codex 里都添加为名为 `codedag` 的 marketplace，插件在两家 Agent 里的标识都是 `codedag@codedag`。这几个命令都不需要登录，也不要求当前目录是用 `cdg init{:sh}` 初始化过的项目。插件能做什么、日常怎样管理，见[管理 CodeDAG Guide 插件](/zh/docs/guides/guide-plugin)。

安装和更新只对之后新开的 Agent 会话生效，所以已经开着的会话要先退出，再用 `claude --resume{:sh}` 或 `codex resume{:sh}` 恢复，才能用上新的插件。

## 选择目标 Agent [#targets]

四个子命令都用下面的选项选择处理哪个 Agent 的插件：

| 选项 | 处理哪个 Agent 的插件 |
|---|---|
| `--claude` | Claude Code |
| `--codex` | Codex |
| `-a`、`--all` | Claude Code 和 Codex |
| 省略 | 同 `--all` |

省略或写 `--all` 时，`install` 与 `update` 只处理本机装有的 Agent。

## cdg plugin install [#install]

```bash title="Terminal"
cdg plugin install [--claude | --codex | --all] [-s <范围>]
```

`cdg plugin install{:sh}` 为目标 Agent 安装插件，Agent 里还没有 `codedag` marketplace 时先添加它。安装范围由 `-s` / `--scope` 指定，取值是 `user`、`project` 和 `local`，默认是 `user`。各范围的区别见[安装范围](#scopes)。`user` 范围在任何目录都能安装；而 `project` 与 `local` 装在运行命令时所在的那份检出里，所以要在 Git 仓库中运行。

```bash title="Terminal"
# 为本机装有的所有 Agent 安装，User 范围
cdg plugin install
# 只为 Claude Code 安装，Local 范围
cdg plugin install --claude -s local
```

已经装过插件时，`install` 不会重装，也不会改变范围：只要在当前位置能看到这个 Agent 的插件，不论它装在哪个范围，命令都直接跳过。例如装过 User 范围之后，在任何仓库里再运行 `cdg plugin install --scope project{:sh}` 都不会生效。要换范围，见[更换安装范围](#change-scope)。

## 安装范围 [#scopes]

通过 CodeDAG 安装插件时，Claude Code 和 Codex 都可以选 User、Project、Local 三种范围，默认是 User。三种范围的区别在于启用插件的配置写在哪里，由此决定插件在哪里生效、是否随仓库共享：

| 范围 | 在哪里生效 | 配置写在哪里 | 适合 |
|---|---|---|---|
| `user`（默认） | 这台电脑上的所有仓库与副本 | 你的用户目录下 Claude Code 或 Codex 的配置，不写入任何仓库 | 个人使用，或者在多个仓库里使用 CodeDAG |
| `project` | 这个仓库，配置提交之后随仓库共享给团队 | 当前检出中受版本管理的 `.claude/settings.json` 或 `.codex/config.toml`；Claude Code 的这份文件还写明 `codedag` marketplace 来自哪个仓库 | 希望团队成员打开这个仓库时都能用上插件 |
| `local` | 当前这份检出，Claude Code 还包括同一仓库的其他 worktree；不随仓库共享 | 被 Git 忽略的 `.claude/settings.local.json` 或 `.codex/config.toml` | 只想在一个仓库里试用，不影响其他仓库和团队成员；Codex 要求仓库没有提交 `.codex/config.toml` |

Codex 的 Project 与 Local 写的是同一个文件 `.codex/config.toml`，区别在于它提交进仓库还是被 Git 忽略。CodeDAG 只增删这个文件里插件的条目，所以你写在里面的其他 Codex 设置保持原样。

### Project 范围 [#project-scope]

Project 范围的配置随项目仓库共享。其他成员拉取之后运行 `cdg init{:sh}`，CodeDAG 就会按这份配置把插件装好，不再询问范围，见[新成员接入](/zh/docs/guides/team-sharing#onboarding)。

运行过 `cdg init{:sh}` 的成员一般不用再做什么，但有两种情况需要再做些处理：

- **初始化时跳过了插件安装。**
- **用 Claude Code 时，在同一台电脑上另 clone 了一份仓库：** 这是因为 Claude Code 按检出分别登记 Project 安装，原来那份检出里的安装不算在新 clone 里。Codex 的插件安装则由这台电脑上的所有项目共用，所以 Codex 在新 clone 里不用再装。

这两种情况下，`cdg plugin status{:sh}` 都会显示 `Sync: broken`，运行 `cdg plugin update{:sh}` 就能装上。

### Local 范围 [#local-exclude]

Local 范围的配置写在被 Git 忽略的文件里，所以只在本机生效。忽略规则由 CodeDAG 在安装时写进仓库的 `info/exclude`（普通仓库就是 `.git/info/exclude`）。这是 Git 只在本机生效的忽略文件，所以装 Local 范围不需要改动团队共享的 `.gitignore`。两家 Agent 写的文件不同：

- **Claude Code：** 用的是 Claude Code 原生的 Local 范围，启用项写进 `.claude/settings.local.json`。
- **Codex：** Codex 并不原生支持 Local 范围，所以 CodeDAG 把启用项写进项目的 `.codex/config.toml`，并让 Git 忽略整个文件。这样，你写在这个文件里的其他 Codex 设置也只在本机生效。

Codex 的 Local 范围适合两类仓库：个人项目，以及团队约定不提交 `.codex/config.toml`（已写进 `.gitignore`）的仓库。Codex 的 Local 范围要让 Git 忽略整个文件，所以只能装在这个文件没被 Git 跟踪的仓库里。已经用上 Codex 项目配置的仓库通常都提交了这个文件，这时 Codex 只能用 User 或 Project 范围。

不推荐把 Codex 的 Local 范围装在还没有这个文件、也没有约定不提交它的团队仓库里。在这样的仓库里也能装上，但团队之后可能会提交这个文件。到那时，你拉取或检出这次提交，Git 会直接用仓库里的版本覆盖你本地那份文件，既不报错也不提示，你写在里面的其他设置也就丢了。已经装在这样的仓库里时，可以这样处理：

- **改用 User 范围：** User 范围不在仓库里写任何文件，也就不会被覆盖，做法见[更换安装范围](#change-scope)。
- **和团队约定不提交这个文件：** 把 `.codex/config.toml` 写进 `.gitignore`，这个仓库就成了上面推荐的那一类。
- **继续用 Local 范围：** 把你写在这个文件里的其他设置另外备份，被覆盖之后再合并回去。

在同一仓库的其他 worktree 里也开会话时，两家同样不同。Claude Code 的各个 worktree 共用主 worktree 里的 `.claude/settings.local.json`，所以装一次，各个 worktree 都会启用；Codex 的 Local 范围则只在安装的那份检出里生效，所以要在每个 worktree 里分别安装。

## cdg plugin status [#status]

```bash title="Terminal"
cdg plugin status [--claude | --codex | --all]
```

`cdg plugin status{:sh}` 为每个 Agent 输出一组状态，最后一行 `Action` 写明下一步要做什么，照着处理即可。输出中有两项容易误读：

- **`Sync: up to date` 不等于 GitHub 上的最新版本：** 命令不联网，`Available version` 是 Agent 上一次刷新 `codedag` marketplace 时取得的版本，所以 `up to date` 只说明已安装的版本与这个版本相同。Claude Code 默认不自动刷新 marketplace，因此这种情况在 Claude Code 里更常见。想确保用上最新版本，直接运行 [`cdg plugin update`](#update)。
- **`Sync: update available, local changes` 不一定说明你改过插件：** 命令无法判断插件文件是否被改过时，也按改过处理。什么情况下会这样、怎样处理，见[没改过插件，却显示有本地修改](/zh/docs/troubleshooting/troubleshooting#plugin-local-changes)。

### 多个范围同时存在时 [#multiple-scopes]

同一个 Agent 的插件同时出现在几个范围里时（例如你装了 User 范围，仓库里又有团队提交的 Project 范围），`Scope` 会列出这些范围。`Enabled` 则是当前目录实际生效的启用值，其中 Local 优先于 Project，Project 优先于 User。

Codex 有一处会让人意外：在 `/plugins` 里停用插件，改的是用户级配置，而 Codex 的项目配置优先于用户级配置，所以这样停用，对装着 Project 或 Local 范围的项目不起作用。只想在这样的项目里自己不用插件时，见[各范围卸载之后](#after-uninstall)。

### 版本兼容 [#compatibility]

插件与 CLI 分开发布，版本号不必相同。插件声明它支持的最低 CLI 版本，以及验证过的 CLI 版本，`CLI compatibility` 据此显示本机 CLI 落在哪一档。显示 `compatible` 时不用处理，另外两种显示是：

- **`CLI too old (requires <最低版本> or later)`：** 本机 CLI 低于插件支持的最低版本，要[升级 CLI](/zh/docs/get-started/installation)，否则 Agent 可能用到本机还不支持的命令或参数。
- **`newer than verified (verified with <已验证版本>)`：** 本机 CLI 比插件验证过的版本新。这时不用处理，因为新版 CLI 会保留已发布插件用到的命令、参数和含义。想让 Agent 知道新版 CLI 增加的用法，更新插件即可。

## cdg plugin update [#update]

```bash title="Terminal"
cdg plugin update [--claude | --codex | --all] [--reset-local-changes]
```

`cdg plugin update{:sh}` 先让 Agent 从 GitHub 刷新 `codedag` marketplace，再把已安装的插件更新到最新版本。插件装在 User 范围时，在任何目录运行一次就够了。

安装损坏时，命令只把插件修复好，不刷新 marketplace，也不更新到最新版本。修复装上的是本机 marketplace 副本里的版本，这个版本可能已经落后；而且修复之后，`cdg plugin status{:sh}` 也可能显示 `up to date`。所以修复之后要再运行一次，才会更新到最新版本。

Claude Code 的插件装在其他仓库的 Project 或 Local 范围时，要到那个仓库里运行一次，才会更新那里的安装，因为命令只更新当前位置能看到的范围。Codex 则不同：它的插件文件由这台电脑上的所有项目共用，所以在任何一个装着它的位置更新一次，所有项目的安装都随之更新。

### --reset-local-changes [#reset-local-changes]

插件文件被改过时，`update` 默认保留修改，这次不更新这个插件。在终端里运行时，命令会先询问是否换回发布的内容，默认不换。加上 `--reset-local-changes`，命令就不再询问，先把改过的插件备份，再换成插件仓库中最新发布的内容；即使没有新版本，改过的文件也会换回发布时的样子。

```bash title="Terminal"
cdg plugin update --reset-local-changes
```

备份放在 CodeDAG 的全局目录（默认是 `~/.codedag`）下的 `plugin-backups/claude-code/` 或 `plugin-backups/codex/`。每个 Agent 只保留最近的一份备份，下一次备份时就会被覆盖，所以其中还想要的修改要及时移走。想长期保留的编排要求适合写进 CLAUDE.md 或 AGENTS.md，原因见[按自己的习惯定制编排](/zh/docs/guides/guide-plugin#customize)。

## cdg plugin uninstall [#uninstall]

```bash title="Terminal"
cdg plugin uninstall [--claude | --codex | --all]
```

`cdg plugin uninstall{:sh}` 卸载当前位置能看到的所有安装，所以它没有 `--scope` 选项。

### 卸载哪些安装 [#uninstall-targets]

在 Git 仓库里运行时，能看到的是这份检出的 Project、Local 范围和 User 范围；在仓库之外运行时，只能看到 User 范围。所以卸载哪些安装分两种情况：

- **只装了 User 范围：** 在任何目录运行，卸载的都只是 User 范围，结果一样。
- **这份检出里还装着 Project 或 Local 范围（包括团队提交的 Project 范围）：** 在仓库里运行，会把它们和 User 范围一起卸载，这台电脑上其他仓库的会话也就用不上插件了。只想卸载 User 范围时，到 Git 仓库之外的目录运行。

### 各范围卸载之后 [#after-uninstall]

各范围卸载之后，还有下面这些后果：

- **User 范围：**
  - **Codex：** 插件只是停用，插件文件还留在这台电脑上，因为其他项目的 Project、Local 范围可能还在用这份文件。要连文件一起删除，按卸载输出里给出的命令操作。
- **Project 范围：** 改的是团队共享的配置，这个改动提交之后，整个团队都不再加载插件。所以只想自己不用时，避免在仓库里卸载，按 Agent 改用下面的做法：
  - **Claude Code：** 用 Claude Code 自己的 `claude plugin disable codedag@codedag --scope local{:sh}` 只在本机停用。
  - **Codex：** Codex 的项目配置优先于用户级配置，所以不能只对自己停用。确实不想用时，在你自己的 `~/.codex/AGENTS.md` 里写明在这个仓库中不使用 CodeDAG 插件即可。
- **Local 范围：**
  - **Codex：** `.codex/config.toml` 是 Codex 自己的配置文件，通常卸载只删掉插件的条目，文件和其他设置都留着。但删掉插件的条目后文件里什么都不剩时，命令会连文件一起删除。卸载同时移除了 CodeDAG 加的[忽略规则](#local-exclude)，留下的文件之后怎样处理，取决于仓库是哪一类：
    - **团队约定不提交这个文件的仓库：** `.gitignore` 仍然忽略它，不用处理。
    - **个人项目：** 文件会作为未跟踪文件出现在 `git status` 里。它就是这个项目的 Codex 配置，直接提交即可；不想提交，就自己为它加一条忽略规则。
    - **还没有这项约定的团队仓库（不推荐的用法）：** 文件同样会出现在 `git status` 里。这时它只是一份普通的 Codex 配置文件，怎样处理，与团队讨论后约定即可。
  - **Claude Code，同一仓库有多个 worktree 时：** 各个 worktree 共用主 worktree 里的 `.claude/settings.local.json`，所以在其中一个 worktree 里卸载，其他 worktree 的插件也会停用。要在那里继续用，在那个 worktree 里运行 `claude plugin enable codedag@codedag --scope local{:sh}`，其中 `--scope local` 不能省。

## 更换安装范围 [#change-scope]

已安装的插件不能直接改范围，要先卸载，再用新的 `--scope` 安装，最后开一个新的 Agent 会话。

两条命令都要在正确的位置运行。卸载要在能看到旧安装的地方进行：旧范围是 Project 或 Local 时，就是装有它的那份检出。新范围是 Project 或 Local 时，安装也要在目标检出里运行。只换一家 Agent 的范围时，两条命令都加上 `--claude` 或 `--codex`，另一家的插件保持原样。

下面把两家 Agent 的插件都从 User 范围换到仓库 `~/code/my-app` 的 Project 范围：

```bash title="Terminal"
cd ~/code/my-app
cdg plugin uninstall
cdg plugin install --scope project
```

因为卸载是在仓库中运行的，原来 User 范围的安装也一并卸载了。这台电脑上的其他仓库因此不再加载这个插件，需要时要在那里另行安装。新写入的 `.claude/settings.json` 和 `.codex/config.toml` 要提交到项目仓库，团队成员才能共享。

反过来，从 Project 范围换回 User 范围时，同样先在这个仓库里卸载，再用 `--scope user` 安装。这次卸载改动了仓库中的项目配置，所以这个改动同样要提交到项目仓库。
