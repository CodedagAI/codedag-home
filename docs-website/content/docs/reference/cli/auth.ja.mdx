`cdg auth{:sh}` には 3 つのコマンドがあり、それぞれ CodeDAG へのログイン、ログアウト、現在のアカウントの確認に使います。どのディレクトリでも実行でき、プロジェクトの中にいる必要はありません。ログイン状態はコンピューターごとに保存され、同じコンピューター上のすべてのプロジェクトが 1 つのログインを共有します。`--help` を除くと、`cdg auth login{:sh}` には [`--no-browser`](#login-no-browser)、`cdg auth status{:sh}` には [`--local`](#status-local) というオプションが 1 つずつあります。ログインが必要な理由、ログインが必要なコマンド、ログイン状態の有効期間は、[ログインとアカウント](/ja/docs/account/login-and-account)を参照してください。

## cdg auth login [#login]

```bash title="Terminal"
cdg auth login [--no-browser]
```

このコマンドは、ブラウザーで Google アカウントを使って CodeDAG にログインし、ログイン状態をこのコンピューターに保存します。ある Google アカウントで初めてログインすると、同時にそのアカウント用の CodeDAG アカウントが作成されるため、事前の登録は必要ありません。

ログインは、コマンドを実行したコンピューターのブラウザーで完了させる必要があります。そのため、SSH のリモートセッション、コンテナー、GUI のないサーバーではログインできません。[デスクトップのブラウザーがない場合](/ja/docs/account/login-and-account#no-browser)を参照してください。

実行するとブラウザーでログインページが開くので、5 分以内にログインを完了してください。間に合わなかった場合は、もう一度実行します。ブラウザーが開く前にコマンドがエラーで終了した場合は、このコンピューターから CodeDAG に接続できていません。[ログインに失敗する、または繰り返しログインを求められる](/ja/docs/troubleshooting/troubleshooting#sign-in-problems)を参照してください。

すでにログインしている状態で実行すると、ログインの手続きをもう一度行います。成功すると、このコンピューターにあった元のログインが、新しいログインに置き換えられます。今回のログインが完了しなかった場合、元のログインはそのまま残ります。

普段は、このコマンドをわざわざ実行する必要はありません。`cdg init{:sh}`、`cdg dag submit{:sh}`、`cdg auth status{:sh}` は、まだログインしていないことがわかると、先に同じログインの手続きへ案内し、そのあとで元のコマンドの処理を続けます。このコマンドを単独で実行する必要があるのは、主に、アカウントを切り替えるときと、このコンピューターがログインしていないために、キューで待っているワークフローが `on-hold` で止まったときです。

### --no-browser [#login-no-browser]

`cdg auth login --no-browser{:sh}` は、ブラウザーを開かずに、ログイン URL を表示して待機するだけです。この URL は、このコンピューターのどのブラウザーで開いてもかまいません。CLI がログインするのは、そのブラウザーで確認したアカウントです。次の 2 つの場合に向いています。

- **自動化されたログイン：** スクリプトやエージェントがブラウザーを操作してログインを完了させる場合は、コマンドの標準出力から URL を取得し、自分が操作するブラウザーで開けます。
- **複数の CodeDAG アカウントを別々のブラウザーでログインしている場合：** デフォルトのブラウザーを経由せず、目的のアカウントでログインしているブラウザーで直接 URL を開けます。

URL は、CLI を実行しているこのコンピューターで開く必要があります。[デスクトップのブラウザーがない場合](/ja/docs/account/login-and-account#no-browser)を参照してください。

環境変数 `CODEDAG_NO_BROWSER=1` も同じ働きをしますが、ログインを始めるすべてのコマンドに作用します。`cdg auth login{:sh}` のほか、まだログインしていないときの `cdg init{:sh}`、`cdg dag submit{:sh}`、`cdg auth status{:sh}` も対象で、ログインが完了すると元のコマンドの処理がそのまま続きます。自動化された環境では、ログインはこれらのコマンドから始まることが多いため、その場合は環境変数を使います。指定できる値は `1` だけで、設定していない場合や空の値の場合は通常どおりブラウザーが開きます。

## cdg auth logout [#logout]

```bash title="Terminal"
cdg auth logout
```

このコマンドは、このコンピューターの CLI からログアウトし、このコンピューターに保存されているログイン状態を削除します。Web コンソールとほかのコンピューターでのログインには影響しません。ログアウトが、キューで待っているワークフローにどう影響するかは、[ログアウトとアカウントの切り替え](#switch-account)を参照してください。

## cdg auth status [#status]

```bash title="Terminal"
cdg auth status [--local]
```

オプションなしで実行すると、このコマンドは、ログイン中のアカウント、サブスクリプションのステータス、現在の期間のクレジットの利用量を表示します。各項目の意味は、[クレジットと利用状況を確認する](/ja/docs/account/credits-and-subscription#check-usage)を参照してください。

### --local [#status-local]

`cdg auth status --local{:sh}` は、このコンピューターに保存された認証情報だけをもとに、ログイン済みかどうかを判定します。ネットワークには接続せず、ブラウザーでのログインに進むこともありません。そのため、スクリプトやエージェントが、ログインの必要なコマンドを実行する前に使うのに向いています。終了コードは、ログイン済みなら 0、未ログインなら 1 です。表示されるのはユーザー ID だけで、メールアドレス、サブスクリプション、クレジットは表示されません。ログインがサーバー側ですでに無効になっている場合でも、ログイン済みと表示されます。

## ログアウトとアカウントの切り替え [#switch-account]

このコンピューターの CLI で別のアカウントを使うには、別の Google アカウントでログインし直してから、現在のアカウントを確認します。

```bash title="Terminal"
cdg auth login
cdg auth status
```

複数のコンピューターで 1 つのアカウントを共有する方法と、ログアウトのルールの全体は、[ログアウト、複数のコンピューター、アカウントの切り替え](/ja/docs/account/login-and-account#sign-out)を参照してください。

ログアウトもアカウントの切り替えも、すでに実行が始まっているワークフローには影響しません。キューで待っているワークフローに実行の順番が来た時点で、このコンピューターの CLI は、そのワークフローを投入したアカウントでログインしている必要があります。そうでない場合、ワークフローは `on-hold` で止まり、後ろに並んだワークフローも一緒に待つことになります。ログインするか元のアカウントに切り替えてから、`cdg dag recover <ワークフロー>{:sh}` を実行すれば続行できます。
